# Исследование

Здесь лежит всё, что относится к **построению модели**. В продукт (`backend/`,
`frontend/`) ничего отсюда не входит: модель приезжает туда готовым артефактом
в `riskml/artifacts/`, а этот каталог исключён из Docker-контекста.

## Что где

| Путь | Что это |
|---|---|
| `risk.ipynb` | итоговый ноутбук, выполненный, с сохранённым выводом всех ячеек |
| `results.json` | метрики, выгруженные ноутбуком; из них собираются документы и по ним сверяется `riskml/train.py` |
| `REPORT.md` | отчёт по исследованию (генерируется из `results.json`) |
| `slide.md` | материал на 5 минут защиты |
| `starter_1.ipynb` | исходный стартовый ноутбук из условия кейса |
| `requirements.txt` | окружение для ноутбука; у бэкенда своё, в `backend/requirements.txt` |
| `build/` | генератор ноутбука: `risk.ipynb` собирается из частей, а не правится руками |
| `experiments/` | черновые эксперименты — то, что пробовалось и не вошло в решение |

## Почему ноутбук собирается скриптом

`risk.ipynb` — это 152 ячейки. Править их вручную в JSON неудобно и легко
сломать, поэтому источник правды — модули в `build/nbparts/`, а ноутбук
собирается из них:

```bash
cd build
python build_notebook.py        # собрать research/risk.ipynb из частей
cd ..
python -m nbconvert --to notebook --execute --inplace risk.ipynb
cd build && python make_docs.py # пересобрать REPORT.md и slide.md
python check_notebook.py ../risk.ipynb   # проверить, что ошибок нет
```

Ноутбук выполняется примерно за 9 минут и находит данные сам — и из корня
репозитория, и из этой папки.

## Черновые эксперименты

`experiments/` — это то, что запускалось по дороге: сравнение моделей, отбор
признаков, тюнинг, вложенная кросс-валидация, перенос на математику. Файлы
`out_*.csv` — их результаты. Эти скрипты **не** нужны ни для сборки продукта,
ни для переобучения; они оставлены как след того, какие гипотезы проверялись
и почему часть из них отброшена.

```bash
cd experiments
python exp09_final.py L2      # например, сравнение финальных конфигураций
```

## Связь с продуктом

Единственное, что связывает исследование и продукт, — это `riskml/`:
`riskml/pipeline.py` содержит дословную копию пайплайна из ноутбука, а
`riskml/train.py` обучает по нему модель и **сверяет метрики с `results.json`**,
падая при расхождении больше 0.01. Так продукт не может незаметно разъехаться
с исследованием.
