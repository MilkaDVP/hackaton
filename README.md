# Предсказание незачёта

Хакатон УрФУ, кейс 6. По анкете студента, заполненной в начале года,
требуется ранжировать группу по риску не набрать проходной балл и назвать
признаки, на которых держится это ранжирование.

Два результата, оба в `risk.ipynb`:

1. **Топ-K студентов по риску** — ранжирование и выбор K, блок 18.
2. **Три признака с наибольшей важностью** — с направлением и оценкой
   устойчивости, блоки 16–17.


## Запуск в три команды

```bash
python -m venv .venv && .venv\Scripts\activate     # Windows
pip install -r requirements.txt
jupyter lab risk.ipynb                              # затем Restart & Run All
```

LightGBM, XGBoost и CatBoost **не нужны** для запуска: они участвуют только
в блоке 9 «Какие модели пробовали», импорты обёрнуты в `try/except`, и без них
ноутбук проходит целиком — в таблице сравнения у этих строк встанет
«не установлено». Кому нужна полная таблица:
`pip install -r requirements-optional.txt`.

Или без Jupyter, одной командой:

```bash
python -m nbconvert --to notebook --execute --inplace risk.ipynb
```

Первый прогон — около 15–20 минут: основное время занимает перебор 60 сочетаний
параметров леса и permutation importance. Результаты складываются в `cache/`,
повторный прогон занимает меньше минуты. Кэш инвалидируется сам при смене
параметров или данных — чистить его руками не нужно.

## Главные результаты

Всё измерено на 30 независимых разбиениях (5 частей × 6 повторов, зерно 1),
отдельных от тех, на которых модель настраивалась. Знак ± — разброс между
разбиениями.

| Что | ROC-AUC | PR-AUC | Выиграно разбиений |
|---|---|---|---|
| Базовый случайный лес, без контрольных | 0.830 ± 0.032 | 0.494 ± 0.081 | — |
| Настроенный лес (лист ≥ 10, 30 % колонок) | 0.836 ± 0.035 | 0.495 ± 0.081 | 23 из 30 |
| **Смесь трёх моделей — финал** | **0.843 ± 0.036** | **0.515 ± 0.076** | **25 из 30** |
| Для сравнения: с оценками за контрольные¹ | 0.966 ± 0.010 | 0.844 ± 0.059 | — |

Ориентир: 0.5 — жребий, доля незачётов в группе — 15.4 %.
¹ измерено на разбиениях отбора: режим с контрольными в работе не используется.

**Выбор семейства моделей.** Десять моделей на тех же 20 разбиениях,

Обе верхние строки — модели семейства случайного леса, обе входят в финальную
смесь. Настроенный лес обгоняет лучший бустинг на 0.028, выигрывая 18 разбиений
из 20. XGBoost четвёртым участником смеси даёт −0.003 на разбиениях отбора
и −0.002 на разбиениях подтверждения. Оба проигравших класса моделей
рассчитаны на объёмы, которых здесь нет: 649 строк, 100 положительных случаев,
39 колонок, большинство из которых двоичные.

**Топ-K по риску.** Все 649 строк упорядочены по риску out-of-fold.
При K = 130 (20 % выборки) recall 0.64, precision 0.49, lift ×3.2:
66 из 130 отобранных строк относятся к отрицательному классу.

**Три признака с наибольшей важностью** (уровень 2):

| | Признак | Разделение | В тройке |
|---|---|---|---|
| 1 | `school` | MS 30 % против GP 7.6 % | в 100 % замеров |
| 2 | `failures` | 0 — 9 %, 1 — 46 %, 3 — 64 % | в 100 % замеров |
| 3 | `higher` | `no` 48 % против `yes` 12 % | в 76 % замеров |

Первые два неразличимы между собой: 0.093 против 0.087 при разбросах 0.035
и 0.021 — порядок внутри пары не определён.

**`absences` не вносит вклада при ненулевой связи с целевой.** Средние 3.5
против 4.6, медианы 2.0 и 2.5; permutation importance +0.0009 при собственном
разбросе 0.0055 — 12-е место из 39 и ноль попаданий в тройку за 25 замеров.
Коэффициент логистической регрессии при этом +0.392: связь есть, вклада нет,
информация дублируется тремя признаками выше.

**Бенчмарк без обучения.** Правило `failures >= 1` или `higher == 'no'` даёт
список из 136 строк и 63 положительных случая из 100; модель при том же K — 65.
На этом K они неразличимы, что согласуется с результатом по важностям: сигнал
сосредоточен в тех же колонках. Различие в том, что правило задаёт единственное
K = 136, а модель допускает любое.

**Границы применимости.** Перенос на математику на уровне 2 даёт 0.631.
Падение локализуется в одном признаке — `school`: разброс долей по школам
0.23 на португальском против 0.05 на математике, тогда как у `failures`
он 0.55 → 0.57 и у `higher` 0.36 → 0.34. Признак кодирует свойство пары
«предмет × школа», а не свойство строки. Из трёх признаков переносятся два.

## Как устроена проверка

Три вещи, без которых цифрам выше нельзя было бы верить:

* **`G3` никогда не в признаках.** Целевая сделана из неё, и модель с `G3`
  внутри показала бы почти идеальный результат, не умея ничего. В блоке 6
  стоит ассерт, который валит ноутбук при утечке.
* **Только парное сравнение.** Разброс между разбиениями ≈ 0.04, поэтому любые
  два варианта считаются на **одних и тех же** разбиениях, и смотрим мы на
  разность по каждому плюс на число выигранных разбиений.
* **Отбор и подтверждение разделены.** Параметры и веса выбирались на 20
  разбиениях с зерном 0, а итоговые числа измерены на 30 других с зерном 1.

Permutation importance считается строго на тех студентах, которых модель
не видела при обучении, и усредняется по 25 замерам. Встроенный
`feature_importances_` не используется: он завышает важность колонок
с большим числом значений.

## Структура репозитория

```
risk.ipynb          основной ноутбук, 22 блока, проходит Restart & Run All
src/scoring.py      prep / fit_blend / load_model / predict_risk / explain
                    ноутбук импортирует их, интерфейс будет вызывать те же
student-por.csv     649 студентов, португальский язык — на нём учимся
student-mat.csv     395 студентов, математика — на ней проверяем перенос
starter_1.ipynb     стартовый ноутбук организаторов, оставлен как есть
requirements.txt    зафиксированные версии, всё обязательное
requirements-optional.txt  lightgbm / xgboost / catboost, только для блока 9
cache/              кэш тяжёлых блоков (в .gitignore)
models/             финальная модель, создаётся блоком 21 (в .gitignore)
```

`models/` и `cache/` не хранятся в репозитории: и то и другое полностью
пересоздаётся прогоном ноутбука.

## Для будущего интерфейса

```python
import sys; sys.path.insert(0, "src")
from scoring import load_model, predict_risk, explain

model = load_model("models/")
risk = predict_risk(group_df, model)     # оценка риска для каждой строки
card = explain(group_df, i, model)       # значения трёх факторов для студента i
```

`predict_risk` возвращает **место в очереди внутри переданной группы**
(от близких к 0 до 1.0), а не вероятность. Подавать нужно всю группу
целиком, а не одного человека.
